# Problem 7: 10001st prime

## The problem

Listing the first six prime numbers gives 2, 3, 5, 7, 11 and 13, so the 6th
prime is 13. What is the 10001st prime number?

Source: [Project Euler problem 7](https://projecteuler.net/problem=7).

## Small experiments

A number is prime when no smaller prime divides it, and only primes up to
its square root need checking: a composite $n$ always has a prime factor $p$
with $p^2 \le n$. So the list of primes found so far is exactly the tool for
testing the next candidate.

Take the candidate 91 and the primes below it. Remainders on division by 2,
3, 5 and 7 (the primes with $p^2 \le 91$) decide the question.

```rix edu
[2, 3, 5, 7] |>> (p) -> {: p, 91 % p };
[2, 3, 5, 7] |>> (p) -> {: p, 97 % p };
```

91 leaves remainder 0 on division by 7, so it is composite ($7 \times 13$).
97 leaves a nonzero remainder every time, and $11^2 = 121 > 97$, so 97 is
prime.

`HasFactorIn` walks the prime list from position `i`, stopping with null as
soon as the square of the prime passes `n`, or with 1 as soon as a prime
divides it.

```rix edu
HasFactorIn(n, primes, i) -> {?
    primes[i]^2 > n ? _;
    n % primes[i] == 0 ? 1;
    $(n, primes, i + 1)
};
known := [2, 3, 5, 7, 11, 13];
HasFactorIn(91, known, 1) ##@ == 1;
HasFactorIn(97, known, 1);
```

The second result is null, shown as `_`: no factor found.

## General solution

After 2, every prime is odd, so candidates step by 2. `NextPrime` tries
candidates until one has no factor. `FirstPrimes` keeps a growing list and
appends to it in place with `Push!` until it is long enough. The loop is the
five-part form `{@ init; condition; body; update; after }` with the update
slot left empty, and the list as the result.

```rix edu
NextPrime(primes, candidate) -> HasFactorIn(candidate, primes, 1) ?: $(primes, candidate + 2) ?_ candidate;
FirstPrimes(count) -> {@::@ primes := [2, 3]; primes.Len() < count; primes.Push!(NextPrime(primes, primes.Last() + 2)); ; primes };
FirstPrimes(6);
FirstPrimes(6).Last() ##@ == 13;
```

That is the list from the statement. Some further checks against well-known
values: the 25 primes below 100, and the 100th and 1000th primes.

```rix edu
firstHundred := FirstPrimes(100);
(firstHundred |>? (p) -> p < 100).Len() ##@ == 25;
firstHundred.Last() ##@ == 541;
FirstPrimes(1000).Last() ##@ == 7919;
```

## Answer

Building the list of 10001 primes takes a couple of seconds, since each
candidate is divided only by primes up to its square root.

```rix expensive edu
answer := FirstPrimes(10001).Last();
answer ##@ == 104743;
```

The 10001st prime is **@{answer}**.
